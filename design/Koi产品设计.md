# 需求：设计一个名为 Koi 的智能浏览器 Agent

**目标**：重新设计一个"既聪明又高效"的浏览器 Agent，取名 **Koi**。

## 总体设计思路

Koi 不做"一个超级 Agent"（不指望一个大模型包办一切），而是四种角色各司其职的组合：

- **Planner 负责想方向**：定目标拆解和路线，不管每一步的细节；
- **ReAct 负责走路**：观察→决策→执行→验证的小循环，一步一步把路走完；
- **Reflection 负责纠错**：卡住、走偏、验证失败时分析原因，把建议喂回循环；
- **Memory 负责成长**：记住进度、历史和技能，让 Koi 越用越快、同类错误不重犯。

## 核心分工

- **手脚**：用 Vercel 的 agent-browser（https://agent-browser.dev/ ，Rust CLI，snapshot 返回带 @ref 的无障碍树，click/fill 按 ref 操作，daemon 常驻，支持 && 串联命令）负责所有浏览器操作，零改造直接使用；
- **大脑**：自研，包含以下核心模块。

## 核心流程与模块

主流程规划图：

```
                     User Task
                         |
                         v

                  +--------------+
                  |   Planner    |
                  |   任务规划    |
                  +--------------+
                         |
                         v

                  +--------------+
                  |   Context    |
                  |  当前任务状态 |
                  +--------------+
                         |
        --------------------------------
        |              |               |
        v              v               v

     ReAct Agent   Skill Memory   Budget Manager

        |
        v

   Observe → Decide → Execute → Verify

        |
        v

   agent-browser
```

流程说明：用户任务经交互层进入 Planner 拆解成子目标清单；Context 维护当前任务状态（计划进度、最近动作、语义状态、反思建议），是 ReAct 每步决策的唯一依据；ReAct Agent 跑"观察→决策→执行→验证"循环，Skill Memory 提供技能命中走捷径，Budget Manager 全程管预算兜底；执行最终落到 agent-browser。验证不通过或子目标完成时回到 Planner 重规划。

### 管线模块（按流程顺序）

1. **交互层**（入口/出口）：接收自然语言目标（模糊表达如"接着看昨天的剧"，结合记忆补全）；执行中实时展示进度（当前子目标、动作、截图）；敏感/不确定动作的人工确认（登录、支付、验证码时暂停等用户介入）；结束时汇报结果，目标不明确时先追问再开工；
2. **任务规划器 Planner**：接到目标先产出子目标清单（每条带可验证的完成标准）；计划是活的，卡住或页面偏离预期时重规划，不推倒重来；
3. **观察 Observer**：通过 agent-browser snapshot 获取页面元素表（@ref 无障碍树），提炼与任务相关的语义状态，两次观察做 diff 让后续模块只看"变了什么"；
4. **决策 Decision**：双路径——快路径（小模型一次请求从元素表选操作+目标，覆盖 90% 步骤）；慢路径（置信度低/连续无进展/关键动作时升级大模型深度思考）；技能命中时直接走技能命令链，0 次模型调用；
5. **执行 Executor（驱动适配层）**：唯一与 agent-browser CLI 交互的模块，把决策翻译成 click/fill 等命令执行；注意 @ref 不跨导航复用、动作后必须重新 snapshot；
6. **验证 Validator**：动作级（页面 diff 是否符合预期，防 @ref 失效的静默 no-op）、子目标级（按 Planner 的完成标准核对，代码判断不问模型）、任务级（DONE 后独立核查，不轻信模型）；
7. **主循环 + 预算**：驱动"观察→决策→执行→验证"循环转起来，决定何时完成、何时回 Planner 重规划；硬预算（步数/慢调用次数/token/时长）兜底，超限体面退出并汇报进度。

### 横切模块（放最后，服务整条管线）

8. **反思-记忆层**（一层，两个职责）：
   - **记忆**：任务内进度（短期）+ 历史任务记录（跨任务）+ 技能库（成功轨迹蒸馏成参数化的 agent-browser 命令模板，实现"越用越快"）；
   - **反思**：事中卡住/验证失败时分析原因给建议（如"弹窗挡住了先关弹窗"），喂回 Decision；事后成功蒸馏技能、失败总结教训入库；
   - 与管线的接口：开工时给 Planner 提供历史经验和现成技能；执行中给 Decision 提供技能匹配和反思建议；收工时把本次轨迹写入记忆。

## 设计原则

- 智能分层花钱：平庸步骤走快路径，困难步骤才唤醒慢思考；
- 经验必须沉淀：第二次做同类任务显著变快；
- 模型只选择不构造：模型输出只能是"选第几号元素"，永不直出坐标/选择器/JS；
- 一切声称都要验证。

## 已知的坑要兜底

非语义化网页（div 绑 onclick 无 role，国内网站常见）在无障碍树里不可见，需要预留降级通道：截图+视觉模型看图选点、CDP 探测 click 事件监听器补齐元素清单。

## 交付要求

整体规划文档（不要代码细节），包含：

- 架构图；
- 每个模块的职责和出场时机；
- 用一个真实场景（如"接着看昨天的电视剧《XXX》，在腾讯视频"）从头到尾串一遍所有模块的协作流程；
- 分阶段实施路线。

# Koi 产品定位与长期愿景

**Koi 是一个快速、稳定、能够自主完成日常事务和复杂工作的个人 AI 浏览器助手。** 用户用文字或语音说出想做什么，Koi 自主规划、操作浏览器、处理异常并完成任务。

## 核心思想
针对浏览器场景做到极致，专注于“做”事情。把交互体验，便捷性，稳定性，准确性，速度做好。

## 一、三大核心使用场景

1. **日常任务：操作浏览器干平时的任务事情。** 如"帮我在腾讯视频接着看昨天的电视剧《XXX》"——自动打开网站、查观看历史、定位剧集、从上次进度续播。类似：继续看昨天的文章、搜索资料、定机票/酒店，商品购买。并且加上云端爬虫，帮你监控数据，数据有更新时主动提醒。
2. **主动提醒：根据你的使用生成记忆，主动给你推送你信息。推送你关注的信息、推送天气、推送新闻。用户可以说一些感兴趣的东西，然后AI主动提醒。比如在设置里面说：当天气有变化时，通知我。这样的云端监控，自动检测地区天气变化，有需要时提醒。**
3. **工作自动化：用自然语言执行复杂流程，可重复执行。** 如"访问 A 网站取今天的产品数据，按编号查 B 网站的价格库存，算差价，生成 Excel 报表"——自动拆解任务、依次访问、提取、计算、出结果。未来支持把流程保存下来，一句"重新执行昨天的产品价格分析"即可复用。适用于数据收集、跨站查询、报表制作等重复性办公。
4. **个人知识管理：随时收藏和整理资料。** 如浏览时说"把这篇文章保存到笔记，记录网址，总结重点"——自动识别当前网页，提取标题/网址/正文，存入笔记工具。未来支持跨网页总结、历史资料检索、个人知识库。

## 二、未来扩展方向

定时任务（每天早上自动收集行业新闻）、长期记忆（继续昨天未完成的任务）、个人技能库（把成功的复杂操作保存成可反复执行的技能）。

## 三、产品形态

跨平台桌面应用（先 Windows/macOS，后 Linux）。常驻后台，全局快捷键唤醒简洁输入框，支持文字和语音。简单任务直接执行；复杂任务后台持续运行并实时展示进度；登录、付款等重要操作请求用户确认，允许随时暂停或接管。初期不自研浏览器，优先操作用户现有浏览器。

## 四、五个产品特点

1. **快速**：简单任务几秒完成，复杂任务减少不必要的模型调用；
2. **稳定**：自动验证结果，出错能恢复，不反复执行无效操作；
3. **智能**：用户只描述目标，Koi 自己规划步骤；
4. **易用**：一个快捷输入框即用，无需学习自动化工具；
5. **可成长**：历史记忆 + 技能复用，重复任务越来越快。

## 五、开发路线

| 版本 | 主要目标 |
| --- | --- |
| V0.1 | 跑通浏览器 Agent 核心闭环 |
| V0.2 | 桌面应用、快捷输入框、进度展示 |
| V0.3 | 复杂任务规划、失败恢复、人工接管 |
| V0.4 | 长流程自动化与技能复用 |
| V0.5 | 文章收藏、笔记集成、个人知识管理 |
| V1.0 | 跨平台、语音交互、长期记忆及稳定的日常使用体验 |

**最终愿景：让 Koi 成为每个人的个人浏览器助手。** 既能在几秒内完成简单日常操作，也能独立执行几十上百步的复杂工作——用户把目标交给 Koi，把时间留给真正需要自己思考和决策的事情。


# 发散思考：
1、把AI现在的能力，针对部分场景做到极致，把交互，提醒都做好。让人感觉在某些场景就是感觉你有一个真实的助手。
2、本地控制自己浏览器，云端分配也分配一个环境，给后续手机适配。像一些监控，持续进行的放在服务持续运行。
