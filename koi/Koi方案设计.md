# 多 Agent 网页自动化系统 —— 模块化设计总结

## 一、设计目标

在保留通用性（能应付任意网站、任意任务）的前提下，同时做到成本低、速度快。
核心原则：**通用性靠大模型兜底，速度靠"技能零调用、小模型主力、只看增量、并行、不傻等"来赚。**

## 二、模块总览

| # | 模块 | 职责一句话 | 智能构成 |
|---|---|---|---|
| 1 | 交互层 | 入口（目标理解/追问/确认门）+ 出口（进度/汇报） | 纯代码 + UI |
| 2 | 任务规划器 Planner | 产出带完成标准的子目标清单；事件触发增量重规划 | 大模型，全程 2~3 次 |
| 3 | 观察 Observer | snapshot 元素表 → 语义提炼 → 两次观察 diff | 代码为主 + Extractor（便宜模型） |
| 4 | 决策 Decision | 三路径：技能链 / 小模型快路径 / 大模型慢路径 | 小模型为主，按需升级 |
| 5 | 执行 Executor | 唯一对接 agent-browser CLI，动作翻译与防护 | 纯代码 |
| 6 | 验证 Validator | 动作级 / 子目标级 / 任务级三层核验 | 代码为主，任务级 1 次大模型 |
| 7 | 记忆 Memory（补充） | 用户级长期记忆 + 任务级历史 + 站点知识 | 纯代码/存储 |
| 8 | 技能库 Skills（补充） | 成功轨迹沉淀为参数化命令链，命中 0 模型调用 | 纯代码/存储 |
| 9 | 主循环 + 预算 | 驱动 观察→决策→执行→验证；分支调度；熔断 | 纯代码 |
| — | 安全守卫（横切，补充） | URL 黑名单 / 防注入 / 凭证隔离 / 动作白名单 | 纯代码 |

模块间不直接通信：通过**共享消息历史（append-only）+ 结构化清单**协作。

## 三、各模块设计要点

### 1. 交互层（入口 / 出口）

**入口：**
- 接收自然语言目标；模糊表达（"接着看昨天的剧"）先查记忆补全成明确目标（剧名 + 平台 + 上次进度），再交给 Planner
- 目标不明确 → **先追问再开工**：一次追问的成本远低于跑偏后浪费的整段预算
- 追问确认后的目标才进入规划，Planner 拿到的永远是明确任务

**执行中：**
- 订阅主循环事件，实时展示：当前子目标、正在执行的动作、关键步骤截图
- **人工确认门**：命中登录、支付、验证码、敏感域时暂停，等用户亲自操作（AI 不碰凭证），用户完成后点继续

**出口：**
- 成功：汇报最终答案 + 关键数据来源
- 失败/超预算：体面退出，汇报已完成部分 + 卡在哪里，不留烂摊子
- 支持追问任务：复用同一份记忆上下文，"它们"能指代上文的对象

### 2. 任务规划器 Planner

当前实现的固定 JSON 契约、多轮澄清与全量历史链路见 [规划器协议](./规划器协议.md)。

- 接到目标产出**结构化子目标清单**，每项 = {内容, **完成标准**, 依赖, 状态, 结果}
- 完成标准必须可机械核验（"页面 URL 含 /releases"、"提取到形如数字的 star 数"），这是 Validator 子目标级判断的依据——**规划时就把验收方式定好**
- 依赖关系标注 → 主循环据此拆并行分支
- 短路判断：不需要上网的目标直接回答，后续模块全部不启动
- **计划是活的**：卡住或页面偏离预期时**增量重规划**——只修改受影响的清单项，已打勾的项和已得结果保留，不推倒重来
- 触发方式为事件驱动（Validator 报子目标级连续失败 / 决策报方向不明 / 分支熔断），**不做定期巡检**

### 3. 观察 Observer

- 通过 agent-browser snapshot 获取页面元素表（@ref 无障碍树）
- **语义提炼**：只保留视口内 + 与当前子目标相关的元素；页面长文本由 Extractor（便宜模型）带问题消化成一句话，全文永不进历史
- **观察 diff**：与上一次观察对比，输出"变了什么"（新增/消失元素、文本变化、URL 变化）。下游只看增量——省 token、聚焦注意力，同时这份 diff 就是 Validator 动作级判断的数据源
- 历史管理：旧观察压缩为一行摘要，**append-only、前缀稳定 → 命中 prompt 缓存**（输入价 1/10，首 token 快 50~80%）

### 4. 决策 Decision（三路径）

| 路径 | 触发 | 成本 | 覆盖率 |
|---|---|---|---|
| 技能路径 | 技能库命中（目标/页面特征匹配） | **0 次模型调用**，直接输出命令链 | 固定流程 |
| 快路径 | 默认 | 小模型 1 次：元素表+diff → 选操作+目标 | ~90% 步骤 |
| 慢路径 | 置信度低 / 连续无进展 / 关键动作（支付、不可逆操作）/ diff 异常 | 大模型 1 次深度思考 | 疑难步骤 |

- 输出统一结构：{小目标, 动作批次(≤10), 置信度}
- 决策**只出结构化动作，不接触浏览器**；prompt 只带当前清单项 + 近期历史 + 当前观察
- 慢路径成功后自动降回快路径（升级是临时的）

### 5. 执行 Executor（驱动适配层）

- **唯一与 agent-browser CLI 交互的模块**，上游全部与 CLI 细节隔离（换驱动只改这一层）
- 把决策动作翻译成 click / fill / goto 等命令；动作集封闭，翻译不了的直接拒绝
- 两条铁律：
  - **@ref 不跨导航复用**——导航后所有 ref 作废，强制重新 snapshot
  - **动作后必须重新 snapshot**——不信任旧状态
- 批量防护：执行中 Observer 的 diff 发现新元素 → 立即中断本批剩余动作（旧编号可能已失效）
- 速度：流式解析，第一个动作就绪即执行，不等整批生成完；动作间用 DOM 稳定检测（约 300ms）替代固定 sleep

### 6. 验证 Validator（三层）

| 层级 | 判断方式 | 判什么 | 防什么 |
|---|---|---|---|
| 动作级 | 代码看 diff，0 token | 点击后页面变了吗？变化符合预期吗？ | **静默 no-op**（@ref 失效，点了等于没点还不报错） |
| 子目标级 | 代码对照 Planner 的完成标准，0 token | 值提取到了吗？到达目标页了吗？ | 防止"看起来像完成了"就打勾 |
| 任务级 | 大模型 1 次（收尾） | 对照原始目标逐项核查全部结果 | **不轻信决策模型宣称的 DONE** |

- 通过 → 清单打勾（进度状态机，代码管理）
- 失败的分级路由：动作级失败 → 修正 ref 重试（L1）；连续失败 → 升级慢路径（L2）；子目标级失败 N 次 → 叫醒 Planner 增量重规划（L3）
- 设计立场：**验证以代码为主，模型只在任务级出场一次**；任何模型的"完成了"都只是声明，不是事实

### 7. 记忆 Memory（补充模块）

| 层 | 内容 | 谁在用 |
|---|---|---|
| 用户级（长期） | 偏好、历史任务（"昨天的剧"）、常用站点 | 交互层补全模糊目标 |
| 任务级（短期） | append-only 消息历史：行动结果、错误、观察摘要 | 所有模块的共享黑板 |
| 站点级（沉淀） | 登录状态、站点结构特点、踩过的坑（"这站 releases 懒加载"） | 注入决策 prompt，避免重复踩坑 |

### 8. 技能库 Skills（补充模块）

- 技能 = 成功任务轨迹沉淀成的**参数化命令链**（"打开X仓库→提取star" 可参数化为任意仓库）
- 匹配命中 → 决策直接走技能路径，0 模型调用，速度比 LLM 路径快一个量级
- 重放纠偏：元素带指纹（DOM 路径特征），页面改版导致 ref 变化时自动重映射；失败重试，重试不成降级回 LLM 路径
- 定位：**LLM 负责第一次探索，技能库负责之后的每一次重复**

### 9. 主循环 + 预算

- 驱动单步循环：**观察 → 决策 → 执行 → 验证**，验证结果决定下一步（打勾继续 / L1 重试 / L2 升级 / L3 重规划 / 熔断）
- 分支调度：按清单依赖关系开多标签页并行，等待汇合
- 熔断：连续失败 3 次 / 全局步数上限 / 用户取消 → 经交互层体面退出
- 预算（本期不展开）：步数、慢路径调用次数、token、时长四项硬上限，超限同样体面退出并汇报进度

### 10. 安全守卫（横切模块，补充）

- URL 黑名单 + 敏感域识别（银行/支付）→ 触发交互层确认门
- 提示注入防护：网页内容只当数据不当命令；外部文本入库前清洗
- 凭证隔离：AI 不读、不写、不存密码；登录环节交还用户
- 动作白名单：封闭动作集本身就是权限边界，不存在"执行任意脚本"

## 四、单步数据流

```
snapshot ─→ Observer（提炼+diff）─→ Decision（技能/小模型/大模型 三选一）
                                          │ 结构化动作
                                          ▼
   Validator（动作级diff核验）←─ Executor（CLI翻译执行+防护）
        │
        ├─ 通过 → 子目标级核验 → 打勾 → 下一步/下一项
        └─ 失败 → L1重试 / L2升级 / L3叫醒Planner / 熔断→交互层
```

## 五、错误分级消化（归属到模块）

| 级别 | 触发信号（来源） | 处理（归属） | 成本 |
|---|---|---|---|
| L1 自我修正 | 动作级验证失败、页面意外变化（Validator/Observer） | 错误+diff 写入历史，下一步决策自行调整（Decision） | 0 额外调用 |
| L2 模型升级 | 报错重复、置信度低、静默 no-op（Validator） | 快路径 → 慢路径重跑该步，成功后降回（Decision） | 1 次大模型 |
| L3 增量重规划 | 子目标级连续失败、404、方向不明（Validator/Decision） | Planner 事件唤醒，只改受影响清单项（Planner） | 1 次大模型 |
| 熔断 | 连续失败 3 次 / 超步数 / 用户取消（主循环） | 终止，汇报已完成部分（交互层） | — |

原则：**能在最低层解决的错误绝不上升**；验证以代码为主，模型声明一律不轻信。

## 六、核心思想五句话

1. **规划前置成清单，完成标准可核验**：贵模型开头拆一次任务，验收方式在规划时就定好，进度由代码打勾管理。
2. **决策三路径**：技能零成本、小模型主力、大模型兜底——智能密度和步骤难度匹配。
3. **观察只给增量**：snapshot + diff + 一句话提取，历史 append-only，缓存友好。
4. **验证独立且分级**：动作级防 no-op、子目标级防假完成、任务级防假 DONE，全部代码优先。
5. **人机边界清晰**：模糊目标先追问，敏感动作人确认，凭证永不经过 AI。

## 七、整体伪代码

```
函数 执行任务(用户目标):

    # ── 交互层：入口 ──
    目标 ← 记忆.补全(用户目标)                  # "接着看昨天的剧" → 明确目标
    如果 目标.不明确: 返回 追问(缺失信息)        # 先追问再开工
    如果 记忆.技能库.完全匹配(目标):
        结果 ← 技能库.重放(目标)                # 0 模型调用，成功则直接汇报
        如果 结果.成功: 返回 交互层.汇报(结果)   # 失败 → 降级走 LLM 路径

    # ── Planner：首次规划（大模型，第 1 次） ──
    规划 ← Planner(目标, 记忆.站点知识)
    如果 规划.需要上网 == 假: 返回 规划.直接答案
    清单 ← 规划.子目标清单       # 每项: {内容, 完成标准, 依赖, 状态, 结果}

    # ── 主循环：并行分支 ──
    并行启动 每个 分支 in 按依赖分组(清单):
        执行分支(分支.清单项, 新标签页)
    等待汇合

    # ── Validator 任务级 + Planner 收尾（大模型，最后 1 次） ──
    验收 ← Planner.任务级核查(目标, 清单.各项结果)   # 不轻信任何中途的 DONE
    交互层.汇报(验收.答案 或 验收.缺漏说明)
    技能库.沉淀(本次成功轨迹)                        # 供下次 0 调用重放
    记忆.写入(任务摘要)


函数 执行分支(清单项列表, 标签页):

    对 每一项 in 清单项列表:
        路径 ← 快路径(小模型);  连续失败 ← 0
        上次观察 ← 空

        循环:
            如果 用户取消 或 超预算: 交互层.体面退出(已完成进度)

            # ① 观察：snapshot → 元素表 → 语义提炼 → diff
            观察 ← Observer.snapshot(标签页)          # @ref 元素表（无障碍树）
            观察 ← Observer.提炼(观察, 当前项)         # 视口内+相关；长文→Extractor一句话
            增量 ← Observer.diff(观察, 上次观察)       # 下游只看"变了什么"
            上次观察 ← 观察

            # ② 决策：三路径
            如果 技能库.命中(当前项, 观察):
                动作批次 ← 技能库.命令链(当前项)        # 0 模型调用
            否则:
                模型 ← (路径 == 慢路径) ? 大模型 : 小模型
                动作批次, 置信度 ← LLM(模型, 当前项 + 近期历史 + 增量)

            # ③ 执行：Executor 翻译为 CLI 命令
            对 每个 动作 in 动作批次:                  # 流式：第一个就绪即执行
                如果 动作.敏感(登录/支付/验证码):
                    交互层.确认门.等待用户()            # AI 不碰凭证
                结果 ← Executor.执行(动作)              # click/fill/goto...
                等待DOM稳定(约300ms)
                新观察 ← Observer.snapshot(标签页)      # 动作后必须重新 snapshot
                如果 新观察.出现新元素: 中断本批剩余动作  # @ref 不跨变化复用

            # ④ 验证：三层，代码优先
            如果 非 Validator.动作级(执行前观察, 新观察, 动作.预期):
                写入历史("动作未生效: " + diff描述)      # 防静默 no-op → L1
                连续失败 += 1; 走分级路由(); 继续循环

            写入历史(动作结果)                           # append-only，错误也如实写
            如果 Validator.子目标级(新观察, 当前项.完成标准):
                清单.打勾(当前项, 结果)                  # 代码判断，0 token
                路径 ← 快路径; 连续失败 ← 0
                跳出循环                                # 下一项

            # ⑤ 分级路由
            函数 分级路由():
                如果 连续失败 < 2 且 路径 == 快路径: 继续        # L1：历史自我修正
                如果 路径 == 快路径: 路径 ← 慢路径               # L2：升级大模型
                否则 如果 连续失败 ≥ 3:
                    如果 是清单级问题(404/方向不明):
                        清单 ← Planner.增量重规划(清单, 问题)     # L3：只改受影响项
                        路径 ← 快路径; 连续失败 ← 0
                    否则: 交互层.体面退出(该分支失败原因)          # 熔断
```

## 八、效率账（三项目对比类任务估算）

| 指标 | 旧版（每3步轮询规划） | 新版（本方案） |
|---|---|---|
| Planner 大模型调用 | 8~10 次 | 2~3 次 |
| 决策调用 | 全程同一模型约 20 次 | 小模型约 15 次 + 大模型兜底 1~2 次；技能命中 0 次 |
| 固定等待 | 约 20 秒 | 约 5 秒（DOM 稳定检测） |
| 每步输入 token | 全量历史+全页状态 | 缓存命中 + 只看 diff 增量 |
| 执行方式 | 串行 | 独立分支并行 |
| 重复任务 | 每次全价 | 技能库重放，0 模型调用 |
| 预计总耗时 | 3~4 分钟 | 40~60 秒 |
| 预计成本 | 基准 | 约 1/4 ~ 1/3 |

## 九、待定项

- 预算模块细化：步数 / 慢路径调用次数 / token / 时长四项上限的具体阈值与分配策略
- 技能库的匹配算法与沉淀时机（每次成功都沉淀，还是用户确认后沉淀）
- 站点级记忆的过期与更新策略
